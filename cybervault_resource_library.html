03 / Practice

Bug bounty methodology

A quick reconnaissance-to-validation workflow from the shared notes.

01 · Google dorking

Tool mentioned: BigBountyRecon. Example search patterns:

site:*.domain.com inurl:"admin | login" | inurl:.php | .asp site:*.domain.com intext:"sql syntax near" | intext:"syntax error has occurred" | intext:"incorrect syntax near" | intext:"unexpected end of SQL command" | intext:"Warning: mysql_connect()" | intext:"Warning: mysql_query()" | intext:"Warning: pg_connect()" site:*.domain.com inurl:/geoserver/ows?service=wfs
02 · Subdomain enumeration
echo domain.com > target.txt subfinder -dL target.txt -all -recursive -o Subs01.txt subenum -l target.txt -u wayback,crt,abuseipdb,bufferover,Findomain,Subfinder,Amass,Assetfinder -o Subs02.txt cat Subs*.txt | anew | tee AllSubs.txt cat AllSubs.txt | httpx -o AliveSubs.txt
03 · URL collection
cat AliveSubs.txt | waybackurls | tee urls.txt cat urls.txt | grep '=' | tee param.txt cat urls.txt | grep -iE '.js' | grep -ivE '.json' | sort -u | tee js.txt
04 · Nuclei vulnerability scanning
nuclei -list urls.txt -t /fuzzing-templates nuclei -list AliveSubs.txt -t /nuclei-templates/vulnerabilities -t /nuclei-templates/cves -t /nuclei-templates/exposures
05 · XSS testing
cat urls.txt | uro | gf xss > xss.txt dalfox file xss.txt | tee XSSvulnerable.txt
06 · Local file inclusion (LFI)
cat AliveSubs.txt | gau | uro | gf lfi | tee lfi.txt nuclei -list target.txt -tags lfi
07 · CORS misconfiguration

Review the Access-Control-Allow-Origin and Access-Control-Allow-Credentials response headers. A reflected origin alone is not proof of an exploitable issue; validate whether sensitive data is accessible in the permitted browser context.

08 · SQL injection
python3 sqlifinder.py -d domain.com sqlmap -m param.txt --batch --random-agent --level 1 | tee sqlmap.txt
09 · Open redirect
cat urls.txt | grep -a -i =http | qsreplace 'evil.com' | while read host; do curl -s -L $host -I | grep evil.com && echo "$host Vulnerable"; done

Basic workflow

Recon → Subdomain enumeration → URL collection → Parameter testing → Vulnerability scanning → Manual validation → Reporting.

Use these workflows only on systems you own or are explicitly authorized to test. Automated scan output is a lead, not proof of a vulnerability. Check current tool syntax and template paths before running commands.
